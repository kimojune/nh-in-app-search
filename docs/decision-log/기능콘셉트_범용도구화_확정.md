# 기능 콘셉트 재설계 — 범용 도구화 확정

- 확정일: 2026-08-21
- 문서 유형: 결정 기록 (decision-log)

## 결정

기능 콘셉트를 "NH 전용 크로스앱 안내 가이드"에서 **"여러 앱으로 쪼개진 기업의 기능을 검색어 기준으로 재매핑해주는 범용 도구"**로 재정의한다. NH 4개 앱 데모는 이 도구의 첫 적용 예시로 그대로 실증한다.

## 왜 다시 짚었나

기존 설계(`docs/B축_MVP_설계.md`)는 NH 4개 앱에 특화된 소비자용 기능으로 문제를 정의했다. 하지만 `docs/NH앱4개_카드검색_as-is결과.md`의 "NH 앱 분리의 조직적 배경" 섹션에는 이미 다음이 확인돼 있었다:

- NH콕뱅크(상호금융)와 NH올원뱅크·NH스마트뱅킹(농협은행)은 감독 체계 자체가 다른 별도 법인이라 앱이 분리돼 있다.
- 이건 NH만의 특수한 문제가 아니라, 여러 앱으로 조직이 쪼개진 기업 전반에 나타나는 구조적 패턴이다(업계 보강 증거 — 한경비즈니스·비즈한국·시사저널e의 슈퍼앱 전환·통합 어려움 보도).

이 근거가 이미 있는데도 해결책을 NH 하나에만 맞춰 설계할 필요가 있는지 의문이 제기됐다(2026-08-21).

## 검토한 대안

| 대안 | 내용 | 채택 여부 |
|---|---|---|
| 현 상태 유지 | NH 전용 소비자 기능으로 그대로 진행 | 기각 — "왜 NH만 해결하는가"라는 평가자 질문에 약함 |
| 완전 범용화 | 회사가 앱·기능·매핑 규칙을 입력하면 실제로 크로스앱 안내가 자동 생성되는 규칙엔진까지 구현 | 기각 — 마감(2026-08-27)까지 6일, 작업량이 너무 큼 |
| **가벼운 범용 프레이밍** | 회사 등록·검색어 매핑 설정 화면 1~2개(비기능 목업)만 NH 데모 앞에 붙여 "범용 도구의 첫 적용 사례"로 보여줌 | **채택** |

## 근거

- 1차 프로젝트 평가 기준의 "문제 정의"(15점)는 "실제 문제와 사용자를 명확히 정의했는가"를 본다 — 이 문제가 NH 하나의 특수 사례가 아니라 일반적인 패턴이라는 걸 보여주면 이 기준에 더 유리하다.
- as-is 조사가 이미 이 일반화 근거(조직적 배경 섹션)를 확보해둔 상태라, 새로운 조사 없이 프레이밍만 바꾸면 된다 — 추가 비용이 거의 없다.
- 실제 동작하는 규칙엔진은 만들지 않기로 했으므로, 이 결정이 NH 4개 앱 데모(`docs/B축_MVP_설계.md`에서 이미 설계된 11개 화면 + 공통 컴포넌트)의 내용·일정에는 영향을 주지 않는다.

## 영향

- NH 데모 자체(화면 명세, 문구, 동의어 매핑)는 변경 없음.
- 설정 화면 2장(회사 등록, 검색어 매핑)이 프로토타입 도입부에 추가됨 — 참가자용 사용성 테스트에는 노출하지 않고, 발표·평가자 시연에서만 사용([`사용성테스트_프로토타입_제작방식_확정.md`](./사용성테스트_프로토타입_제작방식_확정.md) 참고).
