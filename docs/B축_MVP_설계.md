# B축 MVP 프로토타입 설계

- 최종 수정일: 2026-08-20
- 문서 유형: 계속 갱신
- 목적: NH 앱 4개의 인앱 검색 실패를 고치는 MVP를 **ThinkCode에서 직접 구현**할 수 있도록, 화면·문구·동작을 명세한다. 이 문서는 설계만 다루고, 실제 구현은 하지 않는다.

## 가설 검증 (2026-08-20)

"NHPAY 인덱스를 참조하면 된다"는 초기 설계 원칙은 부정확했다 — NHPAY가 검색을 잘하는 건 카드 전용 앱이라 도메인이 좁기 때문이지, 다른 앱에 그대로 옮길 수 있는 우월한 로직이 아니다. 그래서 앱마다 실제로 어떤 방식으로 검색이 실패하는지 가설을 세우고, 추가 스크린샷으로 검증했다.

| 가설 | 검증 방법 | 결과 |
|---|---|---|
| 상품(카드) 자체가 검색 인덱스에 있는지가 성패를 가른다 | 4개 앱에서 "올바른이음카드"(K-패스카드 아닌 다른 실제 카드) 검색 | **채택, 3단계로 확인**: NHPAY(완전) > 올원뱅크(부분, "상품" 탭 있음) > 스마트뱅킹·콕뱅크(전혀 없음, 스마트뱅킹은 "상품 0건") |
| 상품 DB가 없는 앱은 메뉴/화면 라벨의 부분 문자열만 매칭한다 | 스마트뱅킹에 "카드신청" 메뉴가 실제로 존재하는지 직접 확인 | **채택**: 메뉴 자체가 없음(사용자 직접 확인). 콕뱅크는 "NH농협카드 신청" 메뉴가 실제로 있어 "카드발급"/"카드신청"만 성공 |
| 올원뱅크의 "상품" 탭에 K-패스카드가 있을 수 있다 | 올원뱅크에서 "K-패스카드"/"k패스" 검색 후 "상품" 탭 확인 | **기각**: 상품 탭 결과(1~4건)는 전부 무관한 상품("NH K-외국인신용대출" 등, "K" 토큰만 겹침). K-패스카드는 올원뱅크 상품 카탈로그에 없음 |
| 흔한 토큰("카드","신청")이 앱 전체에서 무차별 매칭돼 노이즈를 만든다 | as-is 조사 결과 대조 | **채택**: 스마트뱅킹의 보안카드/OTP, 올원뱅크의 연금·법원등기·NH K-외국인신용대출 등 |

**미확인(추가 검증 안 함, 확인 필요로 남김)**: 부분 문자열 매칭인지 형태소 매칭인지(오타 테스트 안 함), 4개 앱이 완전히 분리된 별도 검색 시스템인지(백엔드 구조 직접 확인 불가 — 정황 증거로만 추정).

## 설계 원칙 (수정)

가설 검증 결과, **앱마다 실패 원인이 다르므로 같은 처방(동의어 매핑)을 다 적용할 수 없다.** 앱을 "정답이 이미 있는데 못 찾는 경우"와 "정답 자체가 없는 경우"로 나눠서 다른 해법을 쓴다.

| 앱 | 상품 인덱스 상태 | 필요한 수정 |
|---|---|---|
| NHPAY | 완전(K-패스카드 포함) | 노이즈 제거만 |
| NH올원뱅크 | 부분(다른 카드는 있지만 K-패스카드는 없음) | 메뉴 경로("NH금융그룹 > NH농협카드") 유지 + 목적지 정밀화 |
| NH콕뱅크 | 없음(메뉴 라벨 매칭만) | 동의어 매핑(검색어 → 기존 메뉴 라벨 연결) + 목적지 정밀화 |
| NH스마트뱅킹 | 없음, 카드 신청 메뉴 자체도 없음 | **크로스앱 안내만 가능** (동의어 매핑 불가 — 보여줄 정답이 이 앱 안에 없음) |

## 검색어 동의어 매핑 테이블 (콕뱅크·올원뱅크의 메뉴 라우팅에만 적용)

이 매핑은 "정답 메뉴가 이미 있는" 콕뱅크·올원뱅크에만 적용한다. 스마트뱅킹은 매핑할 대상이 없으므로 제외한다.

| 검색어 | NHPAY(기준) | 매핑 목표 |
|---|---|---|
| `K-패스카드` | 성공(정확 매칭) | 기준 유지 |
| `경기패스카드` | 성공(정확 매칭) | 기준 유지 |
| `k패스`/`케이패스` | 미검증(as-is 조사에 없음, 예비 테스트에서 콕뱅크 실패 확인) | 콕뱅크·올원뱅크의 기존 메뉴("NH농협카드 신청"/"NH금융그룹 > NH농협카드")로 연결 |
| `카드발급`/`카드신청` | 부분(관련 결과에 무관한 카드 혼입) | 콕뱅크·올원뱅크에서 무관 결과(이응패스, 연금, 법원등기 등) 제거하고 해당 메뉴를 상단에 노출 |

## 앱별 Before → After 명세

각 앱의 "Before"는 as-is 조사 스크린샷([`raw/스크린샷/`](../raw/스크린샷/))에 그대로 있는 실제 화면이다. "After"만 새로 설계한다.

### NH스마트뱅킹 — 크로스앱 안내만 가능

- **Before**: "K-패스카드"/"경기패스카드"/"카드발급"/"카드신청" 전부 실패. 보안카드·OTP 등 무관 결과만 노출. "카드신청" 메뉴 자체가 앱에 없음(2026-08-20 직접 확인). "올바른이음카드"(다른 실제 카드) 검색도 "상품 0건". 참고: [`raw/스크린샷/NH스마트뱅킹/`](../raw/스크린샷/NH스마트뱅킹/)
- **After**: 이 앱 안에는 보여줄 정답이 없으므로, 동의어 매핑 대신 **검색 결과 0건 안내 카드**(아래 참고)를 카드 관련 검색어에서 노출해 NHPAY로 안내한다.

### NH콕뱅크 — 동의어 매핑 + 목적지 정밀화

- **Before**: "K-패스카드"/"경기패스카드" 검색 결과 0건. "카드발급"/"카드신청"은 성공하지만 클릭 시 외부 브라우저(크롬)가 열리며 NHPAY의 **일반 "전체 카드" 목록(79건)**으로 이동 — 특정 카드로 안내하지 않음. 참고: [`raw/스크린샷/NH콕뱅크/크롬nhpay로이동.jpg`](../raw/스크린샷/NH콕뱅크/크롬nhpay로이동.jpg)
- **After (2가지 수정)**:
  1. "K-패스카드"/"경기패스카드"/"k패스"/"케이패스" 검색도 "카드발급"과 동일한 결과("금융 > 카드 > NH농협카드 신청")를 노출하도록 동의어 매핑
  2. 그 메뉴를 눌렀을 때 이동하는 목적지를 "전체 카드 목록"이 아니라 **K-패스카드 상세·신청 직전 화면으로 정밀화** (가능하면 외부 브라우저 대신 인앱 딥링크로)

### NH올원뱅크 — 메뉴 경로 유지 + 목적지 정밀화 (상품 탭 경로는 막힘)

- **Before**: "K-패스카드"/"경기패스카드"는 "NH금융그룹 > NH농협카드" 메뉴로 안내되지만, 클릭 시 이동하는 화면은 K-패스카드가 아니라 **일반 "NH농협카드" 화면(NH Pay 브랜드 프로모션 배너만 있음)**. "카드신청"은 완전 실패(연금·법원등기·NH K-외국인신용대출 등 무관 결과 대량). "상품" 탭에도 K-패스카드는 없음(2026-08-20 확인). 참고: [`raw/스크린샷/NH올원뱅크/NHPay이동(앱아님).jpg`](../raw/스크린샷/NH올원뱅크/NHPay이동%28앱아님%29.jpg)
- **After**:
  1. "k패스"/"케이패스"/"카드신청" 검색에서 무관 결과 제거하고 "NH금융그룹 > NH농협카드"를 상단에 노출 (상품 탭 경로가 아니라 메뉴 경로를 계속 사용)
  2. "NH금융그룹 > NH농협카드" 클릭 시 이동하는 화면을 일반 프로모션 화면이 아니라 **K-패스카드 상세·신청 직전 화면으로 정밀화**

### NHPAY — 노이즈 제거만

- **Before**: 이미 4개 검색어 모두 정확히 처리(성공/부분성공). 유일한 흠은 "카드신청" 검색에 무관한 타지역 카드("이응패스")가 같이 노출되는 것.
- **After**: 이 문제만 가볍게 정리(무관 카드 제거). 나머지는 그대로 유지.

## 검색 결과 0건 안내 카드 (공통 컴포넌트, 특히 스마트뱅킹에 필수)

동의어 매핑으로도 못 잡는 검색어, 그리고 애초에 정답이 없는 스마트뱅킹을 위한 안전망.

> **문구(초안)**: "찾으시는 카드를 다른 곳에서도 확인해보세요"
> 하위 텍스트: "NH페이(NHPAY)에서 카드 상품을 한눈에 볼 수 있어요"
> 버튼: "NHPAY에서 확인하기" → 딥링크 목적지로 이동

NN/g 가이드([`NH앱4개_카드검색_as-is결과.md`](./NH앱4개_카드검색_as-is결과.md)의 "인앱 검색 성공률이 중요한 이유" 참고)의 "결과 없음을 명확히 알리고 대안을 제시" 원칙을 그대로 따른다.

## 딥링크 목적지

모든 "After" 시나리오의 최종 목적지는 하나로 통일한다: **NHPAY의 `K-패스카드` 상품 상세·신청 직전 화면.** (현재 NHPAY 자체 검색에서 "K-패스카드" 검색 시 도달하는 그 화면과 동일)

## ThinkCode 구현 시 필요한 화면 목록 (체크리스트)

- [ ] NH스마트뱅킹 검색 결과 화면 — Before(실패) / After(검색 결과 0건 안내 카드만, 로컬 매핑 없음)
- [ ] NH콕뱅크 검색 결과 화면 — Before(0건) / After(동의어 매핑 결과)
- [ ] NH콕뱅크 메뉴 클릭 후 화면 — Before(크롬, 전체카드 79건) / After(K-패스카드 상세 직행)
- [ ] NH올원뱅크 검색 결과 화면 — Before("카드신청" 무관 결과) / After(정리된 결과, 메뉴 경로 유지)
- [ ] NH올원뱅크 메뉴 클릭 후 화면 — Before(일반 NH농협카드 화면) / After(K-패스카드 상세 직행)
- [ ] NHPAY 검색 결과 화면 — Before("카드신청"에 무관 카드 혼입) / After(정리됨)
- [ ] 공통 컴포넌트: 검색 결과 0건 안내 카드

## Before/After KPI 재현 방법

발표·평가 리포트에서 [`원페이저_기획안.md`](./원페이저_기획안.md)의 "성능 지표(KPI)" 표를 그대로 시연하려면:

1. Before 화면에서 "k패스"/"케이패스" 검색 → 결과 없음을 보여준다 (as-is 스크린샷 그대로 재현)
2. After 화면에서 동일 검색어 입력 → 결과 즉시 노출을 보여준다 (스마트뱅킹은 안내 카드 노출로 대체)
3. 두 화면을 나란히 배치하거나 순서대로 시연해 "인앱 검색 성공률 0% → 100%(스마트뱅킹은 크로스앱 안내로 이탈 방지)"와 "잔여 탐색 시간 47초 → 즉시"를 시각적으로 증명한다
