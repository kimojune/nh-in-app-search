# NH 앱 담당 경로 인식 설문 진행안

- 최초 작성일: 2026-08-18
- 최종 수정일: 2026-08-19
- 상태: 응답 수집 중 / V1 파일럿 9건 분리 후 V2 수집
- 문서 유형: 계속 갱신
- 방식: Google Forms 자기응답형 설문
- 대상: 은행 앱 사용자, NH 앱 경험 무관
- 목표 응답 수: 고정하지 않음 — 기능 필요성 판단의 보조 자료

## 목적

정확한 상품명 `K-패스카드`와 발급 목적을 알고 있는 사람이 담당 NH 앱을 식별할 수 있는지 확인한다. 검색어 지식은 평가하지 않는다.

이 설문은 다음 질문에 답한다.

> 사람들은 K-패스카드를 모바일에서 발급하려 할 때 담당 앱과 첫 행동을 알고 있는가?

실제 탐색 성공 여부와 인터넷 검색의 대안성은 [`K패스카드_과제수행테스트_진행안.md`](./K패스카드_과제수행테스트_진행안.md)에 따른 5~8명의 자유 탐색 과제로 별도 확인한다. 설문 응답 수를 채우는 것이 프로토타입 제작의 관문은 아니다.

## 설문 버전 관리

- **V1 파일럿 9건**: 시나리오에 “인터넷에서 정보를 확인했다”는 표현이 있어 포털 재검색을 유도할 가능성이 있음
- **V2 본 응답**: 정보 출처를 제거한 중립 시나리오로 수정

두 버전은 합쳐서 핵심 비율을 계산하지 않는다. 응답 시트에 `설문 버전` 열을 추가해 최초 9건은 `V1_인터넷언급`, 이후 응답은 `V2_중립시나리오`로 표시한다. V1은 설문 개선 과정과 프라이밍 한계를 설명하는 파일럿 자료로만 사용한다.

## 조사 역할

| 조사 | 확인 내용 | 주장 가능한 결과 |
|---|---|---|
| 인식 설문 | 앱 선택, 선택 이유, 확신도, 예상 후속 행동 | 담당 앱 인식 수준과 추가 탐색 의향 |
| 과제 수행 테스트 | 실제 첫 앱, 도달 여부, 시간, 앱 전환, 외부 검색 | 실제 탐색 행동과 막힘 지점 |

두 결과는 별도로 집계한 뒤 함께 해석한다. 설문 응답을 실제 성공률이나 실제 이탈률로 표현하지 않는다.

## 공통 시나리오

설문과 과제 수행 테스트에 같은 조건을 사용한다.

> NH농협에서 대중교통 이용 시 교통비 환급 혜택을 받을 수 있는 `K-패스카드`를 발급하려고 합니다. 이제 모바일에서 카드를 신청하려고 합니다.

상품명을 제공해 검색어 인지도 변수를 통제하고, 담당 앱 식별 문제에 집중한다. 정답 앱이나 구체적인 이동 경로는 알려주지 않는다.

## 설문 문항

| 번호 | 문항 | 형식 | 측정 목적 |
|---|---|---|---|
| 1 | 사용해본 NH 앱 전체 선택 | 체크박스 | 앱별 경험 구분 |
| 2 | 가장 먼저 할 행동 | 객관식 | 담당 앱 식별과 추가 탐색 필요성 |
| 3 | 선택한 가장 큰 이유 | 객관식 | 지식·습관·추측 구분 |
| 4 | 선택 확신도 | 1~5점 | 정답 여부와 확신의 관계 |
| 5 | 첫 방법 실패 시 다음 행동 | 객관식 | 예상 추가 탐색·포기 의향 |
| 6 | K-패스카드 발급·탐색 경험 | 객관식 | 사전 지식 구분 |
| 7 | NH 앱 탐색 중 혼란 경험 | 선택 서술형 | 정성 사례 보강 |

폼 생성 스크립트는 [`../scripts/create-baseline-form.gs`](../scripts/create-baseline-form.gs)를 사용한다.

## 핵심 지표

1. **담당 앱 최초 식별률**: 첫 행동으로 NHPAY를 선택한 비율
2. **추가 탐색 필요 응답률**: 첫 행동부터 인터넷 재검색 또는 문의를 선택한 비율
3. **오답 고확신률**: NHPAY 외 앱을 선택하면서 확신도 4~5점을 준 비율
4. **예상 외부 탐색·포기 의향률**: 실패 후 포털 검색·문의·포기를 선택한 비율
5. **선택 근거 분포**: 실제 지식, 과거 경험, 습관, 앱 이름 추측, 임의 선택의 비율

전체 결과와 함께 다음 세그먼트를 비교한다.

- NHPAY 사용 경험 있음 / 없음
- K-패스카드 발급·탐색 경험 있음 / 없음

표본이 작으면 비율과 함께 응답자 수 `n`을 표시하고 차이를 일반화하지 않는다.

## 병렬 진행 원칙

- 일반 설문 참여자와 과제 수행 참가자는 가능하면 분리한다.
- 같은 사람이 둘 다 참여하면 과제 수행 테스트를 먼저 하고 설문은 나중에 응답한다.
- 과제 수행 참가자의 설문 응답은 일반 설문 표본과 구분해 표시한다.
- 설문 선택지를 먼저 본 사람이 과제에 참여해 발생하는 학습 효과를 피한다.

## 실행 절차

1. Google Apps Script에서 `create-baseline-form.gs`를 실행한다.
2. 모바일 미리보기로 시나리오와 문항 순서를 확인한다.
3. 테스트 응답 2건을 제출해 응답 시트 연결을 확인한다.
4. 테스트 응답을 제거한다.
5. 일반 설문 링크를 배포하면서 과제 수행 참가자 5~8명도 별도로 모집한다.
6. V1·V2 설문과 과제 수행 결과를 서로 다른 표로 집계한다.

## 배포 전 체크리스트

- [ ] 시나리오에 `K-패스카드`는 있지만 정답 앱은 노출되지 않음
- [ ] `사용해본 앱 없음`과 다른 앱을 동시에 선택한 테스트 응답이 없는지 검토
- [ ] 모바일에서 문항과 선택지가 잘리지 않음
- [ ] 이메일 주소를 수집하지 않음
- [ ] 응답 시트가 정상 연결됨
- [ ] 예상 완료시간이 2~3분 이내임
- [ ] 과제 수행 예정자에게 설문을 먼저 보내지 않음

Google Forms 체크박스는 `사용해본 앱 없음`과 다른 앱의 동시 선택을 기본 기능으로 막기 어렵다. 해당 응답이 발생하면 Q1만 무효로 처리하고 나머지 응답은 유지한다.

## 해석 한계

- 응답은 실제 행동이 아니라 시나리오에 대한 예상 선택이다.
- `담당 앱 최초 식별률`을 실제 탐색 성공률이라고 부르지 않는다.
- 실패 후 행동은 실제 이탈이 아니라 예상 행동이다.
- 지인·캠프 동기 중심 표본은 전체 NH 고객을 대표하지 않는다.
- K-패스카드 한 사례의 결과를 다른 금융 기능에 일반화하지 않는다.
- NHPAY 선택 여부만으로 기능 필요성을 확정하지 않는다. 외부 검색을 포함한 실제 과제에서 빠르고 정확하게 공식 화면에 도달하면 별도 기능의 필요성은 낮다.
