## 왜 재개했나

포트폴리오 목적이다. 1차 발표(2026-08-26, 7분, 표지 + 8장)는 끝났고 v2를 만든다. v2 발표는 2026-09-16.

1차 발표에서 남은 것 둘을 이번에 고친다. 라우터 데모 연동이 안 됐던 것, 그리고 발표자가 스스로 과장이라고 판단한 도입 비용 주장(계열사 앱은 4줄만 심으면 된다)이다.

## 메인 가설

> **사용자가 아는 농협은 하나다.**

발표자 원문은 이렇다. "기업에서 분리한 어플리케이션의 목적을 사용자는 알기 어렵다. 왜 나눴는지 사용자가 알아야 하나? 사용자가 아는 농협은 하나고, 기업 사정으로 나뉜 것을 사용자가 알아야 하나?"

사실 주장이 아니라 누가 부담을 져야 하느냐는 당위 주장이다. 그래서 사용자가 실제로 모른다는 것을 표본으로 증명하지 않는다. 알아야만 쓸 수 있게 되어 있다는 사실만 보이면 된다. 그건 실측으로 충분하다.

카드와 라우터는 이 문장을 받치는 예시다. 주장의 주인공이 아니다. 라우터는 대체할 수 있는 수단 중 하나로 소개한다.

```text

05     라우터                            대체 수단 중 하나. 데모     90초
06     노린 것                           목표와 지표               30초
07     잃는 것                           세 항목                  30초

                                                              270초
```

표지 + 9장. 장별 화면 요소와 말할 문장은 [`발표_스피커노트.md`](./발표_스피커노트.md).

06·07·08의 제목을 「노린 것 / 잃는 것 / 얻는 것」으로 맞췄다. 07과 08은 사용자가 정한 이름이고, 06은 그 짝을 채우려고 에이전트가 붙였다. 06이 08과 뜻이 가까워 보일 수 있는데, 06은 의도와 재는 법이고 08은 실제로 좋아지는 것이다. 06 화면의 둘째 줄(지표)이 그 구분을 짊어진다.

## 원칙

- 한 장에 메시지 하나
- 슬라이드 글자는 인용이나 근거를 위에 깔고 결론을 아래에 작게 둔다
- 근거가 부족한 것은 화면에 올리지 않고 말로만 얹는다
- 07은 단정하고 08은 기대로 말한다. 값은 구조에서 나오고 편익은 잰 적이 없다
- 효과 미검증은 09에서 한 번만 말한다 (2026-09-15 변경. 이전 원칙은 데모 직전이었다. 발표자가 마지막에 밝히기로 정했고, 09를 못 한 일이 아니라 남은 과제로 닫으면 뒤집히는 느낌이 줄어든다)
- 표지 문장과 마지막 장 문장이 같다
- 발표 문체는 AI 흔적을 거른다. 줄표, X가 아니라 Y다, 대구, 명사화, 결산 접속어, 과장 어휘를 쓰지 않는다
- 상표 요소는 실측 캡처 인용만 쓴다. 아이콘을 따서 배치하지 않는다. 네이버페이와 신한은 글자로만

### 사용자 정정으로 뒤집힌 것

에이전트가 제시했다가 사용자 확인으로 바뀐 것들이다. 같은 실수를 반복하지 않으려고 남긴다.

```text
매핑을 정할 주체가 필요하다      각 앱을 운영하는 쪽이 자기 소관을 이미 안다. 앱이 넷으로 나뉜 것 자체가 증거다
                            중앙은 정하는 자리가 아니라 검수하고 배포하는 자리다. 값이 아니라 이미 있는 것
운영 구조를 슬라이드에서 설명     회사 사정 설명이라 무게중심이 사용자에서 회사로 넘어간다
                            같은 재료를 사용자 쪽 문장으로 뒤집는다. "회사는 알고 있고 사용자 화면에만 없다"
설계가 학습 측정을 막았다        로그를 안 남긴 건 맞지만 이유는 법률 검토를 아직 안 밟아서다
                            재검색률부터 확인하고 확장을 논의하는 단계 설계로 말한다
자동 검사 건수를 표지에         발표자가 모르는 숫자는 표지에 올리지 않는다
```

### 닫힌 물음: 08 편익과 09 과제

08의 둘째(편익)와 09의 「익힐 장치」(과제)가 부딪쳐 들릴 수 있었다. 2026-09-16에 발표자가 갈랐다. 08은 긍정형으로 "쓰다 보면 그룹사가 나눈 대로 눈에 익는다"만 말하고 근거 줄은 설계 사실(안내 카드가 기능과 담당 앱을 한 쌍으로 보여준다)만 둔다. 09가 "눈에 익는지도 재지 못했다. 익힐 장치는 따로 필요하다"로 한계를 한 번에 받는다. 편익은 08에, 못 잰 것은 09에. 같은 대상을 두 장에서 말하되 역할이 다르다.
