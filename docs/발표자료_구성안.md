# 발표 자료 구성안

- 최종 수정일: 2026-08-25
- 문서 유형: 계속 갱신
- 발표: 2026-08-26 · **5분 안팎**
- 제출: 2026-08-27 (ThinkCode)

**결론을 먼저 말하고, 본문은 피벗 서사로 간다.** 짧은 발표에서 `효과는 못 쟀다`를 뒤에 두면 듣는 사람이 앞부분을 믿었다가 배신당한다. 먼저 깔면 나머지가 전부 `그럼 무엇을 했나`로 읽힌다.

본문 흐름은 [`PROJECT_GUIDE.md`](../PROJECT_GUIDE.md)에 확정된 피벗 서사를 그대로 따른다.

> `초기 저빈도 기능 탐색 가설 → 설문·행동에서 포털 대안 발견 → NH의 슈퍼앱·운영 주체·기술·사용성 제약 조사 → 완전 통합 대신 최소 담당 채널 안내 방식 제안`

이 문서는 **무엇을 말할지와 근거가 어디 있는지**를 적는다. 슬라이드 문장은 직접 쓴다.

## 시간 배분

```text
1  결론 먼저                     25초
2  가설과 반증                   50초
3  그래도 남는 것                50초
4  왜 통합이 아닌가              35초
5  최소 안내로 좁혔다 + 구조      50초
6  ▶ 시연                       50초
7  못 한 것과 다음               40초
                                ─────
                                300초
```

**`설계 판단과 맞바꾼 것`을 따로 두지 않는다.** 피벗 서사 자체가 그것이다 — 완전 통합 대신 최소 안내로 좁힌 것이 이 프로젝트에서 가장 큰 맞바꿈이다. A안 기각은 문서와 질의응답으로 넘긴다.

**안정성과 재현성은 시연 안에서 말한다.** `이 관문은 시연하다 찾아서 막은 것`이 별도 장으로 말하는 것보다 강하다.

            그리고 이 방식이 아주 적은 비용으로 도입된다는 것

**왜 먼저 말하나** — 5분 안에 신뢰를 잃지 않기 위해서다. `HANDOFF.md`에도 `발표에서 먼저 말해야 한다`고 적어뒀다.

## 2. 가설과 반증 · 50초

**말할 것**

```text
처음 가설   이름은 아는 저빈도 금융 기능을 어느 앱에서 처리하는지 못 찾는다

근거        앱을 먼저 여는 15명 중 담당 앱(NH Pay)을 고른 사람   1명
            같은 15명 중 담당 앱이 아닌 것을 고르고 확신도 4~5   7명
            올원뱅크에서 `카드신청` 검색 → 39건, 전부 퇴직연금

그런데      실제로 시켜보니 포털이 70초 만에 신청 직전 화면까지 데려갔다

→ "그럼 만들 필요 없는 것 아닌가" 에서 한 번 멈췄다
```

**화면** — as-is 검색 결과 캡처 한 장. `39건인데 전부 무관`이 눈으로 보이는 것.

**근거** — 설문은 [`raw/260825 NH앱 담당경로 인식설문 응답.csv`](../raw/260825%20NH앱%20담당경로%20인식설문%20응답.csv) 25건. as-is는 [`NH앱4개_카드검색_as-is결과.md`](./NH앱4개_카드검색_as-is결과.md). 행동 관찰은 [`K패스카드_과제수행테스트_진행안.md`](./K패스카드_과제수행테스트_진행안.md).

**이 장의 값어치** — 자기 가설을 스스로 흔든 대목이다. **여기서 멈춘 것을 숨기지 않는 편이 낫다.**

## 3. 그래도 남는 것 · 50초

**말할 것**

```text
못 찾으면 60%가 포털로 간다

포털에 나가면 만나는 화면
  1위    모두의카드 (정부 정책 채널)
  광고   신용카드 관련광고 7건 · 1위 KB국민 K-패스카드

→ 회사는 이 지점부터 고객이 무엇을 보고 고르는지에 관여하지 못한다
```

**화면** — 2026-08-25 네이버 실측 캡처. `raw/스크린샷/Screenshot_20260825_17*_NAVER.jpg`.

**근거** — [`decision-log/포털대체와_공식판별_확정.md`](./decision-log/포털대체와_공식판별_확정.md).

## 4. 왜 통합이 아닌가 · 35초

**가장 먼저 나올 반론이다.** 먼저 답한다.

```text
NH도 슈퍼앱 통합을 추진하고 있다 (언론 보도로 확인)

그런데 완전 통합에는 세 가지가 걸린다
  운영 주체   콕뱅크(상호금융)와 올원뱅크(농협은행)는 감독 체계가 다른 별도 법인
  기술        과거에 앱을 쪼갠 이유 자체가 "하나에 다 담으면 느려진다"였다
  사용성      기능이 과밀해지면 오히려 찾기 어려워진다

합쳐도 다 못 합친다 — 은행 · 상호금융 · 카드 · 보험 · 증권

→ 통합을 기다리는 대신, 지금 구조 위에 얹는다
```

**근거** — [`PROJECT_GUIDE.md`](../PROJECT_GUIDE.md) 개요와 [`NH앱4개_카드검색_as-is결과.md`](./NH앱4개_카드검색_as-is결과.md)의 「NH 앱 분리의 조직적 배경」·업계 보강 증거 3건.

**조심할 것** — 언론 보도는 **`NH가 조직적으로 인지·계획 중이라는 맥락 증거`로만** 인용하기로 2026-08-18에 범위를 좁혔다. `기사가 검색 실패를 증명한다`고 말하지 않는다.

## 5. 최소 안내로 좁혔다 + 구조 · 50초

**말할 것**

```text
해결안   검색어 → 담당 채널 + 역할(완료 · 경유 · 안내) + 다음 행동
         검색 결과를 바꾸지 않는다. 그 위에 안내만 얹는다
         담당 채널은 검색 데이터가 아니라 조직 데이터다

구조     지능은 중앙, 앱은 조회만
           앱 호출부            4줄
           검색당 네트워크       0 B
           변경 없을 때          304 · 수신 0 B
           계열사가 손으로 채우는 칸  2개
```

**화면** — 안내 카드 한 장 + 구조 그림. 카드는 `prototype/설문용_안내카드.html`을 캡처하거나 `router/bank-app.html` 화면.

**근거** — [`prototype/router/README.md`](../prototype/router/README.md).

**조심할 것** — **자동으로 이동시키지 않는다.** 2026-08-22 확정 사항이다. 질문이 나오면 딥링크 백엔드가 범위 밖이라고 답한다.

## 6. 시연 · 50초

**한 장면만 한다.** 0건에서 안내가 붙는 지점이 이 기획의 전부다.

```text
1  앱 탭     콕뱅크에서 `k패스카드` 검색 → 0건, 안내 없음
2  콘솔 탭   계열사 샘플 불러오기 → 등록 요청 → 일괄 검토 요청
             → 일괄 승인 → 승인된 기준 발행
3  앱 탭     동기화 → 200 OK → 같은 검색어에 안내가 뜬다
4  앱 탭     동기화 한 번 더 → 304 Not Modified · 수신 0 B
```

**돌리면서 한 줄 말한다**

> 승인을 건너뛰면 빈 기준이 나가서, 앱은 200 OK를 받고도 아무 안내를 못 띄웁니다.
> **시연하다 그걸 겪고 이 관문을 막았습니다.**

**준비**

```text
prototype/router/console.html
prototype/router/bank-app.html      헤더 오른쪽 `발표 모드` 버튼
```

두 파일을 탭 두 개로 미리 열고, 발표 모드를 켠 뒤 화면 크기를 확인한다. 콘솔은 `전체 초기화`로 깨끗한 상태에서 시작한다.

**아껴둘 것** — 되돌리기, 스냅샷 손상 후 회복. 시간이 남거나 질문이 나오면 보여준다.

## 예상 질문과 답

| 질문 | 답할 것 |
|---|---|
| 효과를 못 쟀는데 좋은 줄 어떻게 아나 | **모른다.** 근거는 문제의 크기와 도입 비용까지다. 그 구분을 1장에서 먼저 밝혔다 |
| 그냥 앱을 합치면 되지 않나 | 4장. 운영 주체·기술·사용성. 합쳐도 다 못 합친다 |
| 포털이 대체하는데 왜 만드나 | 3장. 회사가 그 지점부터 통제력을 잃는다 |
| 계열사가 왜 깔아주나 | 이미 크로스링크를 만들어 뒀다. 없는 건 협조 의사가 아니라 정밀도다 |
| 검색을 고치면 되지 않나 | 담당 채널은 검색 데이터가 아니라 조직 데이터다. 어느 검색 사전에도 그 값이 없다 |
| 왜 앱이 중앙에 물어보지 않나 | 검색당 0 B가 사라지고, 중앙이 멈추면 앱 검색도 멈추고, 검색어가 다른 법인으로 넘어간다 |
| 자동 이동은 왜 안 하나 | 확정 사항이다. 딥링크 백엔드는 범위 밖이다 |
| `86%`는 실측인가 | **아니다.** 샘플 로그 기준 계산이다. 계산은 재현되지만 입력이 예시값이다 |
| 보기를 줬으면 쉬워진 것 아닌가 | 맞다. 검증 설계의 한계로 7장에서 먼저 밝힌다 |
