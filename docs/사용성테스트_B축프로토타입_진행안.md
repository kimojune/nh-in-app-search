# B축 프로토타입 사용성 테스트 진행안

- 작성일: 2026-08-21
- 문서 유형: 계속 갱신
- 대상: 4~8명 (은행 앱 사용 경험 무관, 특정 은행·카드사 제한 없음)
- 예상 시간: 참가자 1명당 10~15분 (Before·After 2단계 합산)
- 프로토타입: [`prototype/b축_사용성테스트_프로토타입.html`](../prototype/b축_사용성테스트_프로토타입.html) — Claude Artifact로 배포된 링크를 참가자 본인 폰 브라우저로 열어 진행

이 문서는 [`K패스카드_과제수행테스트_진행안.md`](./K패스카드_과제수행테스트_진행안.md)(A축, 실제 은행 앱/포털 대상)와 별개다. 이 문서는 **B축 프로토타입 자체**(NH 4개 앱 인앱 검색 Before/After)를 참가자에게 직접 조작시켜 검증하는 테스트다.

## 목적

`docs/B축_MVP_설계.md`에서 설계한 개선(동의어 매핑·목적지 정밀화·크로스앱 안내카드)이 실제 참가자에게도 검색 성공률·소요시간을 개선하는지 측정한다. Before와 After를 **같은 참가자, 같은 매체(이 프로토타입)** 안에서 순서를 바꿔가며 겪게 해 매체 차이로 인한 왜곡을 없앤다(자세한 근거는 대화 결정 사항 — 실제 네이티브 앱과 웹 목업을 직접 비교하지 않고, Before·After 모두 같은 목업 안에서 비교).

## 검증할 것 (트랙 A 평가 기준에서 역산)

- **동작·완성도**: 동의어 매핑 6개 검색어 변형이 참가자가 실제로 입력했을 때도 설계대로 동작하는가
- **성능 지표**: Before 대비 After의 목표 화면 도달률·소요시간·검색 시도 횟수·앱 전환 횟수 — 프로토타입이 자동으로 기록
- **안정성**: 설계 밖 검색어(전혀 다른 표현)를 입력해도 깨지지 않고 "검색 결과 없음"으로 안전하게 처리되는가, 오인 성공(잘못된 화면인데 성공이라 착각)이 발생하는가
- **재현성**: 여러 참가자에게 동일 절차로 진행했을 때 패턴이 일관되는가

## 참가자 배정 — 카운터밸런싱

참가자를 두 조건으로 절반씩 배정한다.

| 조건 | 1단계 | 2단계 |
|---|---|---|
| A | Before | After |
| B | After | Before |

홀수 번째 참가자는 A, 짝수 번째 참가자는 B로 배정한다. 두 조건 다 배정 후에는 "몇 명이 Before를 먼저 겪었는지"가 균형 잡히도록 유지한다.

## 준비물

- 참가자 본인 스마트폰(프로토타입 링크를 그 폰 브라우저로 열어 진행)
- 이 문서의 관찰 기록표(또는 동일한 열의 스프레드시트)
- 프로토타입 자체가 소요시간·검색 시도·성공 여부를 자동 기록하므로, 타이머는 보조용으로만 필요

## 진행 순서

### 1. 진행자 사전 준비 (참가자에게 보이지 않음)

1. 진행자가 본인 화면(또는 참가자에게 건네기 전 참가자 폰)에서 프로토타입 링크를 연다.
2. "회사 등록" → "검색어 매핑 설정" 화면은 **건너뛴다** — 참가자에게 보여줄 필요 없음(발표·평가자 시연 전용, 이 테스트의 범위 밖).
3. "테스트 조건 선택" 화면에서 이번 참가자의 배정 조건(A 또는 B)을 누른다.
4. 화면이 4개 앱 탭 + 검색창이 있는 화면으로 바뀌면, 이제 참가자에게 폰을 건넨다.

### 2. 시작 전 안내 (참가자에게 그대로 읽어줌)

> 지금부터 이 화면에서 특정 카드의 신청 경로를 찾는 짧은 테스트를 진행하겠습니다. 여러분을 평가하는 것이 아니라, 지금 보시는 화면이 얼마나 쉽게 원하는 걸 찾게 해주는지 확인하는 테스트입니다.
>
> 화면 위쪽에 스마트뱅킹·콕뱅크·NHPAY·올원뱅크 4개 탭이 있고, 각 탭 안에 검색창이 있습니다. 평소 은행 앱에서 검색하시듯 자유롭게 입력해보시고, 여러 탭을 오가셔도 됩니다.

### 3. 과제 제시

> 대중교통 이용 시 교통비 환급 혜택을 받을 수 있는 `K-패스카드`를 발급받으려고 합니다. 지금 화면에서 카드 상품 상세 화면까지 찾아주세요. 4개 탭 중 어디를 먼저 봐도 되고, 검색어도 자유롭게 입력하시면 됩니다.

### 4. 1단계 진행

- 참가자가 검색·탭 전환·메뉴 클릭을 자유롭게 진행한다.
- 진행자는 화면 상단의 "진행자" 버튼을 눌러 숨겨진 통제 패널을 열 수 있다(참가자에게는 평범한 앱처럼 보이도록 기본적으로 숨김 상태).
- 목표 화면(공통 목적지)에 도달하면 자동으로 "도달했습니다" 성공 화면이 뜬다.
- 5분이 지나거나 참가자가 포기하면 진행자가 통제 패널의 "이 단계 종료" 버튼을 누른다.
- 프로토타입이 자동으로 계산한 결과 요약(소요시간·검색어·성공 여부)이 뜨면, 관찰 기록표에 옮겨 적는다.

### 5. 2단계 진행

- "2단계 시작" 버튼을 눌러 반대 조건으로 넘어간다.
- 참가자에게: "이번엔 같은 화면인데, 검색이 어떻게 달라지는지 다시 한번 같은 방식으로 찾아주세요"라고 안내한다.
- 4번과 동일하게 진행하고 결과를 기록한다.

### 6. 종료 후 질문

1. 두 번의 시도 중 어느 쪽이 더 쉬웠나요? 왜 그렇게 느꼈나요?
2. 검색이 안 될 때 어떤 행동을 하셨나요? (다른 검색어, 다른 탭, 포기 등)
3. "찾으시는 카드를 다른 곳에서도 확인해보세요" 안내 카드를 보셨다면, 그걸 보고 어떤 생각이 들었나요?
4. 전체적으로 이 방식이 실제 은행 앱에도 있으면 좋겠다고 느끼셨나요?

## 성공 기준

- **성공**: 프로토타입이 자동으로 "목표 화면 도달"을 기록한 경우.
- **실패**: 5분 이내 도달하지 못했거나 참가자가 포기한 경우.
- **오인 성공**: 참가자가 스스로 "찾았다"고 말했지만 실제로는 도달 화면(공통 목적지)이 아닌 경우(예: 콕뱅크·올원뱅크의 Before 오답 목적지에서 멈춘 경우) — 진행자가 그 자리에서 정정하지 않고, 종료 후 질문에서 확인한다.

## 계산할 지표

- Before 목표 도달률 = `Before에서 성공 ÷ 유효 참가자 수`
- After 목표 도달률 = `After에서 성공 ÷ 유효 참가자 수`
- Before/After 소요시간 중앙값 비교
- 순서 효과 = 조건 A(Before 먼저) 참가자의 After 결과와 조건 B(After 먼저) 참가자의 After 결과를 비교해 학습 효과가 크게 나타나는지 확인

## 한계 (미리 명시)

- 실제 네이티브 앱이 아니라 웹 프로토타입이므로, 로그인·설치 등 실제 앱의 마찰은 반영되지 않는다. 다만 Before·After 모두 동일 매체이므로 이 마찰 차이는 두 조건에 동일하게 적용되어 비교 자체는 유효하다.
- 표본 4~8명은 통계적 유의성이 아니라 5일 프로젝트의 소규모 판단 기준이다([`K패스카드_과제수행테스트_진행안.md`](./K패스카드_과제수행테스트_진행안.md)의 "A축 한계 종합"과 동일한 태도).
- 진행자·연구자·판정자가 동일인일 수 있어 판정 편향 위험이 있다.
