# K-패스카드 과제 수행 테스트 진행안

- 작성일: 2026-08-19
- 최종 수정일: 2026-08-20
- 상태: 비공식 예비 테스트 1건 완료 / 정식 5~8명 진행 예정
- 문서 유형: 계속 갱신
- 대상: 은행 앱 사용자 5~8명
- 예상 시간: 참가자 1명당 10~15분

## 목적

정확한 상품명 `K-패스카드`와 발급 목적을 알고 있는 사용자가 평소 방식으로 공식 목표 화면까지 도달하는 과정을 확인한다. 앱과 포털 검색을 모두 허용하며, 인터넷 검색이 빠르고 정확한 대안인지와 검색 이후에도 남는 탐색 비용을 측정한다.

이 테스트는 검색어 지식을 평가하지 않는다. 다음 행동을 측정한다.

- 처음 선택한 앱 또는 포털
- 목표 화면 도달 여부
- 담당 앱 식별 시간과 최종 도달 시간
- 확인한 앱 수와 전환 횟수
- 포털 검색어·확인 결과 수·공식 정보 식별 여부
- 포털에서 앱으로 복귀했는지
- 막힌 지점과 판단 근거

## 검증할 가설

> 담당 앱을 바로 모르더라도 포털 검색이 빠르고 정확하게 공식 신청 경로까지 연결한다면 별도 기능은 필요하지 않다. 포털 검색 후에도 정보 판별·앱 복귀·목표 화면 도달에 큰 비용이나 실패가 반복될 때만 개선 가치가 있다.

### 프로젝트 진행 판단 기준

5명 이상을 테스트한 뒤 전체 과정과 반복 패턴을 보고 판단한다. 외부 검색 자체는 실패가 아니다.

- 대부분이 포털을 포함해 2분 이내 공식 목표 화면에 도달하고 정보 판별·앱 복귀에서 막히지 않으면 기능 제작을 보류한다.
- 여러 검색 결과를 비교하거나 비공식·오래된 정보 때문에 혼란을 겪는 현상이 반복되면 개선을 검토한다.
- 담당 앱을 알아낸 뒤에도 앱 설치·실행·재검색·메뉴 탐색이 반복되면 잔여 탐색 비용으로 기록한다.
- 5분 이내 공식 목표 화면에 도달하지 못하거나 포기하는 사례가 반복되면 문제 가설을 지지한다.

이 기준은 통계적 유의성을 뜻하지 않으며, 5일 프로젝트에서 기능 제작 여부를 결정하기 위한 소규모 판단 기준이다.

## 참가자 조건

- 본인 스마트폰으로 은행 앱을 사용할 수 있는 사람
- NH 앱 사용 경험은 없어도 됨
- "NH 앱을 써봤다"는 실제 NH 거래 여부를 증명하지 않으므로, 앱 경험이 아니라 **NH 계좌를 실제로 쓰는지(주거래 여부)**를 사전 질문에서 별도로 확인하고 관찰 기록표에 남긴다
- 가능하면 NH 실사용 고객과 비고객을 모두 포함
- 사전 배포한 구글폼(인식 설문)을 이미 본 사람은 되도록 피한다. 다만 가용 인원이 한정돼 불가피하게 겹치면 배제하지 않고, 관찰 기록표에 설문 노출 여부를 표시해 해석 시 참고한다 (설문에 NH 앱 목록이 노출돼 있어 첫 행동 선택에 영향을 줄 수 있음)

실제 카드 신청이나 개인정보 입력은 하지 않는다. 테스트 중 앱 설치 또는 로그인 때문에 시간이 지나치게 소요되면 해당 시간은 탐색 시간과 분리해서 기록한다.

## 준비물

- 타이머
- 아래 관찰 기록표 또는 동일한 열을 가진 스프레드시트
- 화면 녹화 기능(참가자가 동의한 경우에만 사용)
- 참가자의 스마트폰과 설치된 NH 앱

화면 녹화에는 이름, 계좌번호, 잔액, 알림 등 개인정보가 포함될 수 있다. 녹화가 꼭 필요하지 않으면 진행자가 행동만 기록한다.

## 성공 기준

### 성공

NHPAY에서 `K-패스카드` 상품 상세 또는 신청 직전 화면에 도달한 경우다. 실제 신청 버튼은 누르지 않는다.

### 보조 경로 성공

다른 NH 앱에서 NHPAY 또는 NH카드의 K-패스카드 화면으로 연결되는 안내를 발견하고, 해당 경로를 따라 목표 화면에 도달한 경우다.

### 실패

다음 중 하나에 해당하는 경우다.

- 5분 이내 목표 화면에 도달하지 못함
- 참가자가 포기함
- 외부 검색 결과만 확인하고 NH의 목표 화면에는 도달하지 못함
- 전혀 다른 카드 또는 관리 메뉴를 목표 화면으로 잘못 판단함

### 시간 측정

- 시작: 진행자가 “시작해주세요”라고 말한 순간
- 종료: 성공 화면 도달, 참가자 포기 또는 5분 경과
- 앱 설치·업데이트·로그인 장애 시간은 별도 기록하고 탐색 시간에서 제외

## 진행 순서

### 1. 시작 전 안내

진행자는 아래 문장을 그대로 읽는다.

> 지금부터 NH농협 앱에서 특정 카드를 찾는 짧은 테스트를 진행하겠습니다. 여러분을 평가하는 테스트가 아니라 앱에서 경로를 찾기 쉬운지 확인하는 테스트입니다. 실제 카드 신청이나 개인정보 입력은 하지 않습니다. 평소 하듯 자유롭게 행동해주세요. 가능하면 무엇을 보고 어떤 생각을 했는지 소리 내어 말씀해주세요. 막히더라도 제가 경로나 정답을 알려드리지는 않겠습니다. 언제든 중단할 수 있습니다.

화면을 녹화할 경우 별도로 동의를 받는다.

> 행동을 나중에 정확히 확인하기 위해 화면을 녹화해도 될까요? 녹화 중 개인정보가 보이면 즉시 중단하며, 동의하지 않아도 테스트에 참여할 수 있습니다.

### 2. 사전 질문

과제를 보여주기 전에 묻는다.

1. 평소 사용하는 은행 앱이 있나요?
2. 다음 NH 앱 중 사용해본 앱이 있나요?
   `NH스마트뱅킹 / NH콕뱅크 / NHPAY / NH올원뱅크`
3. K-패스카드를 직접 발급하거나 찾아본 경험이 있나요?

사전 질문에서 각 앱의 역할을 설명하거나 정답 앱을 알려주지 않는다.

### 3. 과제 제시

아래 과제를 참가자에게 글로 보여주고, 진행자가 한 번 읽어준다.

> NH농협에서 대중교통 이용 시 교통비 환급 혜택을 받을 수 있는 `K-패스카드`를 발급하려고 합니다. 평소 하던 방식으로 카드 상품 상세 또는 신청 직전 화면까지 찾아주세요. 앱이나 인터넷 검색 등 어떤 방법을 사용해도 됩니다. 실제 신청은 하지 마세요.

참가자가 내용을 이해했는지만 확인한 뒤 타이머를 시작한다. **진행자는 특정 앱이나 화면을 미리 열어서 보여주지 않는다. 참가자가 스스로 시작 방법을 선택하게 한다.**

### 4. 과제 진행

진행자는 정답과 관련된 도움을 주지 않고 행동을 기록한다.

참가자가 말을 멈추면 다음 중 하나만 사용한다.

- “지금 무엇을 보고 계신가요?”
- “어떤 생각으로 그 항목을 선택하셨나요?”
- “다음에는 무엇을 해보시겠어요?”

참가자가 정답을 물으면 다음처럼 답한다.

> 지금은 정답을 알려드리기보다 평소라면 어떻게 찾으실지 보고 있습니다. 자연스럽게 계속해 주세요.

로그인·설치 문제로 진행할 수 없으면 화면을 대신 보여주거나 정답을 안내하지 말고, 기술적 중단으로 기록한다.

### 5. 종료 후 질문

타이머를 멈춘 뒤 묻는다.

1. 처음 그 방법을 선택한 이유는 무엇인가요?
2. 어느 지점에서 가장 헷갈렸나요?
3. 각 NH 앱이 어떤 역할을 하는지 알고 있었나요?
4. 다른 앱으로 이동했거나 이동하려 한 이유는 무엇인가요?
5. 원하는 화면을 찾았다고 판단한 근거는 무엇인가요?
6. 인터넷 검색을 사용했다면 공식 정보인지 어떻게 판단했나요?
7. 인터넷 검색만으로 충분히 쉽게 해결됐나요? 가장 번거로운 단계는 무엇이었나요?
8. 현재 앱에서 담당 앱과 이동 경로를 알려줬다면 차이가 있었을까요? 왜 그렇게 생각하나요?

마지막 질문은 해결책에 관한 반응이므로, 과제 수행이 끝난 뒤에만 묻는다. 긍정 답변 자체를 기능 효과의 증거로 사용하지 않는다.

## 비공식 예비 테스트 기록 (정식 표본 제외)

정식 절차(안내 문구·사전 질문·타이머, 진행자 비개입)를 따르지 않고 진행한 예비 테스트 1건. 아래 결과 집계표(정식 5~8명 표본)에는 포함하지 않고 참고 기록으로만 남긴다.

- 참가자: NH 비주거래 고객, 구글폼 설문 미노출
- 진행자가 NH콕뱅크 화면을 먼저 열어서 보여주고 시작함 — **첫 행동 선택 데이터로는 사용 불가** (이후 진행 순서에 "진행자는 특정 앱을 미리 보여주지 않는다"를 명시해 재발 방지)
- 00:21 시작 → 콕뱅크 안에서 "k패스"·"케이패스" 검색, 결과 없음 → 카테고리 메뉴 확인 시도
- 01:08 인터넷 검색으로 전환 → "농협 케이패스" 검색 시 결과 바로 확인
- 01:31 도착 → 설치돼 있던 NHPAY로 이동, 신청 직전 화면 도달 (총 70초, 앱→웹→앱 경로)
- 참고 가치: NH 앱 내 상품명 검색이 실패하는 흐름은 [`NH앱4개_카드검색_as-is결과.md`](./NH앱4개_카드검색_as-is결과.md)의 as-is 조사 결과와 일치하는 실측 사례로, 잔여 탐색 비용(앱 내 검색 실패 → 포털 전환)의 근거로는 유효하다.

## 결과 집계표

테스트 종료 후 참가자별 한 줄로 집계한다.

| ID | NH 경험 | 첫 행동 | 담당 앱 식별(초) | 목표 도달 | 전체 시간(초) | 확인 결과·앱 수 | 공식 정보 식별 | 앱 복귀 | 핵심 막힘 |
|---|---|---|---:|---|---:|---:|---|---|---|
| P01 | 비경험 | 네이버 검색 | 30 | 성공 | 115 | 결과 1·앱 1 | 예 | 성공 | 앱 안에서 상품 재검색 |

### 계산할 지표

- 목표 도달률 = `(직접 성공 + 보조 경로 성공) ÷ 유효 참가자 수`
- 2분 이내 도달률 = `120초 이내 성공한 사람 ÷ 유효 참가자 수`
- 담당 앱 식별 중앙 시간 = 담당 앱을 알아낸 시점의 중앙값
- 전체 탐색 중앙 시간 = 성공 참가자의 목표 화면 도달 시간 중앙값
- 포털 활용률 = `포털 검색을 실제 수행한 사람 ÷ 유효 참가자 수`
- 공식 정보 식별률 = `공식 근거로 담당 앱을 판단한 사람 ÷ 포털 검색자 수`
- 앱 복귀 성공률 = `포털에서 목표 앱으로 복귀한 사람 ÷ 포털 검색자 수`
- 재검색·다중 경로 탐색률 = `결과·앱을 2개 이상 확인한 사람 ÷ 유효 참가자 수`

기술적 중단은 성공률 분모에서 제외하고 건수와 원인을 별도로 보고한다. 포털 검색은 실패나 이탈로 자동 판정하지 않고, 공식 화면 도달에 기여했는지와 이후 비용을 함께 기록한다.

## 결과 해석 원칙

- 참가자 5~8명의 결과를 전체 NH 사용자에게 일반화하지 않는다.
- 정확한 키워드를 제공했으므로 상품명 인지도 문제가 아니라 전체 해결 경로의 효율을 본다.
- 처음 NHPAY를 선택하지 않았거나 포털을 이용한 것만으로 실패라고 단정하지 않는다.
- 포털을 통해 빠르고 정확하게 공식 화면에 도달하면 현재 대안이 충분히 작동한 것으로 해석한다.
- 포털 사용 후에도 정보 판별·앱 복귀·재검색 비용이 반복될 때만 잔여 문제로 해석한다.
- 기존 크로스 앱 링크로 쉽게 성공했다면 새 기능 필요성이 약해질 수 있으므로 그대로 기록한다.
- 가설과 반대되는 결과도 숨기지 않고 문제 정의 수정 근거로 사용한다.

## 테스트 종료 후 다음 결정

### 문제가 확인된 경우

별도 자연어 서비스보다 기존 NH 앱 검색 결과에서 담당 앱과 공식 이동 경로를 제공하는 최소 인앱 핸드오프를 우선 검토한다. 같은 과제와 동일한 성공 기준으로 목표 도달률·시간·재검색을 비교한다.

### 문제가 충분히 확인되지 않은 경우

크로스 앱 안내 기능 제작을 보류하고 다음 중 하나를 선택한다.

- 카드 발급 사례에서 기존 연결의 발견 가능성만 개선
- 다른 기능 사례를 추가 조사한 뒤 문제 범위를 다시 정의
- “문제가 크지 않았다”는 가설 검증 결과로 프로젝트 회고 작성
