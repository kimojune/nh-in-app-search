# 원페이저 기획안 — 저빈도 금융 기능 담당 채널 안내 (K-패스카드 사례)

- 최종 수정일: 2026-08-24
- 문서 유형: 계속 갱신
- 상태: 문제 탐색·프로토타입 검증 진행 중

## 한 줄 요약

저빈도 금융 기능을 찾는 은행 앱 사용자의 외부 검색 의존을 K-패스카드 과제로 탐색하고, 모든 기능을 한 앱에 통합하는 대신 검색어에 맞는 담당 채널과 처리 가능한 경로를 안내하는 저비용 검색 방식을 제안한다.

## 문제 정의

- **초기 가설**: 사용자는 이름을 알고 있는 저빈도 금융 기능도 어느 앱·채널에서 처리해야 하는지 찾기 어렵다. K-패스카드는 이를 관찰하기 위한 대표 과제다.
- **대안 발견**: 사용자 설문과 안내 없는 행동 사례에서 포털 검색이 현실적인 해결 경로로 나타났다. 포털 사용 자체는 실패가 아니며, 처음부터 포털을 선택하는 행동과 앱에서 찾지 못해 전환하는 행동을 구분한다.
- **구조적 제약**: NH도 슈퍼앱으로 기능을 통합하고 있지만, 상호금융·지역농협·농협은행 등 운영 주체가 달라 모든 기능과 채널을 하나로 합치기 어렵다.
- **기술·사용성 제약**: 모든 기능을 한 앱에 구현하기 어렵고, 구현하더라도 기능이 지나치게 많아져 앱 사용성이 나빠질 수 있다.
- **피벗**: 모든 기능을 한 앱에 통합하는 대신, 금융사가 기존 검색에 적용할 수 있는 검색어·기능·담당 채널 매핑과 안내 방식을 설계한다.

## 피벗 판단 구조

포털 검색 검증과 인앱 검색 조사를 서로 독립된 축으로 나누지 않는다. 포털이라는 대안을 발견한 뒤에도 남는 구조적 제약을 조사하고, 완전한 기능 통합보다 작은 해결책을 선택한 하나의 피벗 과정으로 본다.

| 단계 | 확인한 질문 | 판단 |
|---|---|---|
| 초기 문제 탐색 | 은행 앱 사용자는 저빈도 금융 기능의 담당 채널을 찾기 어려운가 | K-패스카드를 대표 과제로 선택 |
| 대안 확인 | 포털 검색이 담당 앱 탐색을 대신할 수 있는가 | 설문과 초기 과제에서 실제 대안으로 관찰되어 별도 기능의 필요성을 재검토 |
| 구조·실현 가능성 조사 | 슈퍼앱 하나에 모든 기능을 통합할 수 있는가 | 운영 주체 분리와 기술·사용성 한계 때문에 완전 통합은 적합하지 않다고 판단 |
| 해결안 최소화 | 통합하지 않고도 탐색을 도울 수 있는 최소 기능은 무엇인가 | 검색어의 상품 카테고리를 판단해 담당 채널만 안내하는 방식으로 피벗 |

## 검증 방법

- **설문(보조)**: 구글폼, 담당 앱 인식 조사, 25건 수집(2026-08-23 응답까지, 계속 수집)
- **자유 탐색 Before(문제 행동)**: 은행·카드사·앱·포털을 지정하지 않고 정확한 상품명(`K-패스카드`)만 제공해 자연스러운 시작 경로와 외부 검색 의존을 관찰
  - 상세: [`K패스카드_과제수행테스트_진행안.md`](./K패스카드_과제수행테스트_진행안.md)
- **안내형 After(해결안 이해)**: 담당 채널 안내를 보고 외부 재검색 없이 올바른 채널과 다음 행동을 결정하는지 관찰

## 현재까지 결과 (2026-08-20 기준)

| 근거 | 내용 |

| 비공식 예비 테스트 1건 | NH 콕뱅크 내 검색 실패 재현 → 포털 전환 → 70초 성공 (정식 표본 제외) |

**해석**: 지금까지 포털 검색은 담당 채널을 모를 때 사용할 수 있는 현실적인 대안으로 관찰됐다. 따라서 모든 기능을 한 앱에 통합해야 한다는 필요성은 약해졌다. 동시에 은행 앱을 탐색 채널로 선택하지 않거나 앱에서 포털로 전환하는 행동은 별도로 측정할 가치가 있다. 정식 참가자는 아직 1명이라 반복 패턴이나 개선 효과는 확정할 수 없다.

## 프로토타입 방향 (확정)

프로토타입은 실제 NH 앱이나 슈퍼앱이 아니다. 금융사가 기존 검색에 적용할 수 있는 검색·안내 방식의 작동 원리를 보여준다. 검색어가 어떤 기능·카테고리에 속하는지 매핑하고, 처리 가능한 담당 채널과 채널별 역할을 표시한다. NH 앱 4개는 첫 적용 사례다.

- 구성: 검색어 동의어·별칭 매핑 / 결과 0건 또는 담당 채널 불명확 시 안내 / 여러 채널의 `완료·경유·안내` 차이 표시
- 사용자 범위: 기능·상품명은 알지만 담당 채널은 모르는 사용자. 자연어 상품 추천과 개인화는 제외
- 운영 제안: 각 담당 조직이 매핑을 등록하고 중앙 운영자가 검수·승인한 뒤 배포
- 이동 범위: 정확한 상품 화면으로 자동 이동시키는 딥링크가 아니라 어디에서 무엇을 할 수 있는지 안내
- 제작 착수: 확정 즉시 시작(2026-08-20), 4일차까지 기다리지 않음 — 아래 "남은 일정"의 병렬화 결정 참고
- **스코프**: 콕뱅크 1개가 아니라 NH 앱 4개(스마트뱅킹·콕뱅크·NHPAY·올원뱅크) 전체에 동일 패턴을 적용한 데모 — as-is 조사에서 이미 4개 앱을 실측·캡처해뒀으므로 새 조사 없이 가능
- **확장 방향**: 카드 외 적금·대출 등 다른 카테고리는 범용 가능성을 보여주는 후속 범위이며, 이번 프로젝트에서 검증된 사실로 간주하지 않는다
- **설계·구현 분리**: 화면·문구·매핑은 [`B축_MVP_설계.md`](./B축_MVP_설계.md)로 먼저 설계하고, 실제 구현은 ThinkCode에서 직접 진행 (평가 용이성)

## 성능 지표 (KPI)

- **주 KPI**: 외부 재검색이나 진행자 도움 없이 올바른 담당 채널과 다음 행동을 결정한 비율
- **Before 행동 지표**: 포털 우선 선택률, 인앱 탐색 후 포털 전환율, 전체 외부 검색 의존률
- **After 보조 지표**: 담당 채널 정확 선택률, 결정시간, 오인율, 도움 요청·포기율, 안내문 이해 여부
- **가드레일**: 최종 과제 성공률, 전체 탐색시간, 잘못된 채널 이동, 선택지 과다로 인한 혼란
- **후행 사업 가설**: 탐색 이탈이 줄면 신청 화면 도달과 신청 전환이 개선될 수 있음. 실제 서비스 데이터 없이는 입증하지 않음

자유 탐색 Before와 안내형 After의 조건이 다르면 두 결과로 직접 개선율을 계산하지 않고, 각각 문제 행동과 해결안 이해의 증거로 구분한다.

## 알려진 한계

- K-패스카드 1개 사례로 저빈도 금융 기능 전체를 대표할 수 있는지는 검증하지 못함
- 참가자 5~8명은 통계적 유의성이 아닌 5일 프로젝트 소규모 판단 기준
- 설문은 사전 노출로 인해 참가자 "처음 행동" 지표에 프라이밍 가능성 있음
- 언론 보도 근거는 카드 검색 실패를 직접 증명하지 않는 맥락 증거로 한정
- 포털 사용은 합리적인 대안일 수 있어 외부 이동을 모두 실패로 판정할 수 없음
- 실제 NH 내부 검색·권한·연동 구조를 모르므로 구현 가능성과 비용 절감을 확정할 수 없음
- 승인 정보의 최신성, 중앙 검수 병목, 계열사 간 담당 충돌 등 운영 리스크가 남음
- 복수 채널 노출은 선택 부담을 다시 키울 수 있고 개인화는 이번 범위에서 제외
- 프로토타입은 실제 앱의 로그인·보안·로딩·딥링크 마찰을 재현하지 못함
