# 원페이저 기획안 — NH 크로스 앱 안내 가이드 (K-패스카드 사례)

- 최종 수정일: 2026-08-20
- 문서 유형: 계속 갱신
- 상태: 검증 진행 중 (기능 필요성 미확정)

## 한 줄 요약

사용자는 자주 쓰지 않는 금융 기능(카드 발급 등)의 발급 경로를 모바일에서 찾기 어려워한다는 가설을, K-패스카드 발급을 대표 사례로 검증한다. 포털 검색만으로 충분히 빠르게 해결된다면, 검증 과정에서 실측된 은행 앱 자체의 검색 결함을 고치는 최소 기능 범위(MVP)로 프로토타입을 만든다. 이 MVP의 적용 범위를 더 많은 검색어·앱·카테고리로 넓히면 그게 곧 "크로스앱 안내 기능"이다 — 둘은 다른 기능이 아니라 같은 것의 적용 범위 차이다.

## 문제 정의

- **출발점**: NH 앱 4개(스마트뱅킹·콕뱅크·NHPAY·올원뱅크)에서 같은 검색어를 넣어도 결과와 연결 방식이 다르다는 현상을 as-is 조사로 확인했다
- **상위 가설**: 이건 "발견 용이성(findability)이 낮은 저빈도 기능" 문제의 한 사례다. 카드 발급 하나로 대표성을 검증하며, 다른 저빈도 기능으로의 일반화는 이번 프로젝트 범위 밖(다음 단계 과제)이다
- **핵심 질문**: 사용자가 담당 채널을 바로 모르더라도, 포털 검색이 빠르고 정확하게 공식 신청 경로까지 연결해준다면 크로스앱 안내 기능이 필요한가?

## 판단 기준

아래 두 기준(축)으로 나눠서 판단한다. **A축은 해결책이 필요한지를 정하고, B축은 그 해결책을 얼마나 넓게 적용할지(커버리지)를 정한다.** "MVP"와 "풀스케일 크로스앱 안내"는 다른 기능이 아니라, 같은 패턴(동의어 매핑·안내카드·딥링크)을 몇 개의 검색어·앱·카테고리에 적용하느냐의 차이일 뿐이다.

| 축 | 질문 | 판정 |
|---|---|---|
| **A축 (필요 여부 판단)** | 포털 검색이 순수 탐색시간 2분 이내로 공식 화면까지 데려다주는가 | 대부분 성공 → 필요 없음, MVP 범위 유지 / 5분 초과·포기 반복 → 필요함, 커버리지 확장 |
| **B축 (커버리지·프로토타입 근거)** | 은행 앱 안에서 정확한 상품명 검색이 되는가 | A축 결과와 무관하게 실패 시 검색엔진 개선(MVP)을 저비용으로 채택. A축이 "필요"면 이 패턴의 적용 범위를 넓힌다 |

## 검증 방법

- **설문(보조)**: 구글폼, 담당 앱 인식 조사, 21건 수집(2026-08-20 기준, 계속 수집)
- **자유 탐색 과제(주 판단)**: 은행·카드사 미지정, 정확한 상품명(`K-패스카드`) 제공, 5~8명 목표
  - 상세: [`K패스카드_과제수행테스트_진행안.md`](./K패스카드_과제수행테스트_진행안.md)

## 현재까지 결과 (2026-08-20 기준)

| 근거 | 내용 |
|---|---|
| as-is 조사 | NH 앱 4개 검색 결과 불일치 확인. 상세: [`NH앱4개_카드검색_as-is결과.md`](./NH앱4개_카드검색_as-is결과.md) |
| 비공식 예비 테스트 1건 | NH 콕뱅크 내 검색 실패(B축 재현) → 포털 전환 → 70초 성공 (정식 표본 제외) |
| 정식 참가자 P01 | 은행·카드사 미지정 조건, 바로 포털 검색 → 삼성카드 공식 모바일웹 → 1분 10초 성공, 막힘 없음 |
| 표본 진행률 | 1/5~6명 |

**해석**: 지금까지 2건 모두 2분 이내 막힘없이 성공했다. A축은 "기능 불필요" 쪽을 가리키지만, 5명 미만이라 아직 판단하기엔 이르다.

## 프로토타입 방향 (확정)

A축 결과와 무관하게, **B축에서 이미 확인된 은행 앱 내 검색 실패**를 프로토타입 대상으로 확정했다. 포트폴리오 트랙 A(PO·기획 트랙)는 동작하는 프로토타입 제출을 요구한다. B축 결함은 A축 결과가 어떻게 나오든 이미 실측 확인된 사실이라, 흔들리지 않는 근거가 된다.

- 후보: 검색어 동의어·별칭 매핑 / 검색 결과 0건 시 안내 카드 / 공식 딥링크 제공 — **앱마다 실패 원인이 달라 적용되는 후보가 다름** (콕뱅크·올원뱅크는 동의어 매핑, 스마트뱅킹은 메뉴·상품 인덱스 자체가 없어 안내 카드만 가능. 상세는 [`B축_MVP_설계.md`](./B축_MVP_설계.md) 참고)
- 제작 착수: 확정 즉시 시작(2026-08-20), 4일차까지 기다리지 않음 — 아래 "남은 일정"의 병렬화 결정 참고
- **스코프**: 콕뱅크 1개가 아니라 NH 앱 4개(스마트뱅킹·콕뱅크·NHPAY·올원뱅크) 전체에 동일 패턴을 적용한 데모 — as-is 조사에서 이미 4개 앱을 실측·캡처해뒀으므로 새 조사 없이 가능
- **스트레치 목표(선택)**: 카드 외 적금·대출 등 다른 카테고리로 확장 — 약 4~5.5시간 추가 소요 예상, 4일차 카드 프로토타입 완성 후 시간이 남을 때만 진행
- **설계·구현 분리**: 화면·문구·매핑은 [`B축_MVP_설계.md`](./B축_MVP_설계.md)로 먼저 설계하고, 실제 구현은 ThinkCode에서 직접 진행 (평가 용이성)

## 성능 지표 (KPI)

포털 검색으로 결국 해결되더라도 은행 앱 자체의 검색 성공률을 KPI로 삼는 이유는 [`NH앱4개_카드검색_as-is결과.md`](./NH앱4개_카드검색_as-is결과.md)의 "인앱 검색 성공률이 중요한 이유"에 근거(신뢰도별 구분)를 정리해 뒀다.

| 구분 | KPI | Before | After |
|---|---|---|---|
| 주 지표 | 인앱 검색 → 목표 화면 도달률 | as-is 조사 기준 NH 4개 앱 중 1개(NHPAY)만 정확히 매칭 | 콕뱅크·올원뱅크는 동의어 매핑으로 매칭, 스마트뱅킹은 크로스앱 안내로 도달 — 4개 앱 전체 도달 재현 (스마트뱅킹은 "검색 매칭"이 아니라 "안내를 통한 도달"임을 구분) |
| 주 지표 | 검색 실패로 인한 잔여 탐색 시간(초) | 예비 테스트 실측 47초 | 프로토타입 적용 시 즉시(수 초 이내) |
| 보조 지표 | 전체 소요시간 대비 잔여 비용 비율 | 예비 테스트 기준 70초 중 47초(67%) | 개선 후 비율 감소 여부 관찰 |
| 보조 지표 | 오인 성공률 | 관찰 예정 | 안내 카드 도입 후 감소 여부 관찰 |

기대 사업 효과(고객센터 문의 감소, 카드 신청 이탈률 감소 등)는 5일 프로젝트에서 직접 측정하지 않으므로, 위 실측 KPI와 섞지 않고 회고에서 "기대 효과"로만 별도 언급한다.
