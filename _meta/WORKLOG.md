## 이 파일에 대하여

이 프로젝트에서 무엇을 하고 있었고 무엇이 남았는지를 추적한다. **에이전트가 쓴다.**

- **세션 시작** — 맨 위 칸을 읽고 `남은 것`에서 이어갈 항목을 고른다.
- **세션 종료 또는 커밋** — 새 칸을 맨 위(`---` 바로 아래)에 덧붙이고 `최종 갱신`을 고친다.
- **파일을 바꾼 턴마다** — 맨 위 `지금` 블록을 덮어쓰고 제목의 날짜를 고친다. 질문·설명만 한 턴에는 쓰지 않는다. 사람이 다른 일을 하다 돌아왔을 때 이 세 줄만 읽고 복귀하기 위한 것이며, 아래 칸들의 요약이므로 새 사실을 여기서 만들지 않는다. 방향이 아직 정해지지 않았으면 `검토 중 — 방향 미정`처럼 확정 전임을 드러내 쓴다. 날짜가 오래됐으면 믿지 않는다.
- 확정된 사실은 이 파일에 두지 않고 `PROJECT_GUIDE.md` 또는 `docs/decision-log/`에 반영한다. 여기 남는 것은 진행 상황과 남은 일뿐이다.
- 채울 내용이 없는 줄은 비워두지 말고 지운다.
- 작업 중 새 질문이 생기면 조사하지 않고 `_meta/INBOX.md`에 적고 현재 작업으로 돌아온다.
- 종료조건을 바꾸고 싶으면 먼저 이유를 `_meta/INBOX.md`에 적고, "지금 작업의 진짜 일부인가"를 확인한 뒤에만 바꾼다.

### 이 프로젝트에만 해당하는 것

이 프로젝트는 **2026-08-28에 종료**했다(`PROJECT_GUIDE.md`). 그러므로 이 파일에 쌓이는 것은 기능 작업이 아니라 저장소 정리·문서 정합화다. 종료 시점의 프로젝트 내용은 아래를 본다.

| 찾는 것 | 어디 |
| --- | --- |
| 확정 사항·미확인 사항 | `PROJECT_GUIDE.md` |
| 왜 그렇게 정했는지 | `docs/decision-log/` |
| 종료 시점의 미해결 항목 | `_meta/HANDOFF.md` 「미해결로 남은 것」 |
| 종료 전 세션별 진행 기록 | `_meta/ACTIVE_WORK.md` |

`_meta/ACTIVE_WORK.md`와 `_meta/HANDOFF.md`는 워크스페이스 규격에서는 2026-08-31에 폐지된 문서지만, 이 프로젝트에서는 **종료 시점 기록으로 남겨두기로 했다(2026-09-01)**. 새 진행 기록은 두 파일에 덧붙이지 않고 이 파일에 쓴다.

## 칸 서식

모든 프로젝트가 같은 서식을 쓴다. 프로젝트 성격에 따라 칸 이름을 바꾸지 않는다 — 이름이 갈리면 프로젝트를 옮길 때마다 서식을 다시 익혀야 하고 서식 하나를 고칠 때 여러 곳을 고쳐야 한다.

| 칸 | 무엇을 쓰나 |
| --- | --- |
| 문제 | 이 칸에서 해결하려는 것 한 줄 |
| 종료조건 | 무엇이 정해지거나 끝나면 이 칸을 닫는가 |
| 한 일 | 바꾼 파일 경로와 커밋 해시. 서술하지 않는다 |
| 검증 | 무엇으로 확인했나. 확인하지 못했으면 `미검증` |
| 결론 | 한 줄. 아직 없으면 `아직 없음` |
| 이유 | 결론이 그렇게 된 근거 |
| 남은 것 | 체크리스트. 끝난 항목은 지우지 않고 `[x]`로 바꾼다 |
| 미결정 | 이 칸에서 못 정한 것. 질문 자체는 `_meta/INBOX.md`로 보낸다 |

에이전트를 전환할 때도 별도 인수인계 문서를 만들지 않고 이 칸을 채운다 — `한 일`·`검증`·`남은 것`이 인수인계에 필요한 전부다.
