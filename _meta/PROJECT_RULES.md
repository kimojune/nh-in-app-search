# Portfolio 1차 개인 프로젝트 규칙

이 문서는 이 회차 프로젝트에서 작업하는 모든 에이전트가 따르는 규칙의 단일 기준이다. 워크스페이스 루트의 `WORKSPACE_RULES.md`를 함께 따른다.

- 이 폴더를 독립된 빌드업 프로젝트로 취급한다.
- 현재 상태와 확정·미확인 사항은 `PROJECT_GUIDE.md`를 단일 기준으로 삼는다.
- 조사·분석 문서는 `docs/`, 수정하지 않는 과제 원본과 앱 캡처는 `raw/`에 둔다.
- 사용자 직접 조사 메모인 `생각정리노트.md`를 임의로 정리하거나 덮어쓰지 않는다.
- 사용자 조사 결과와 가설을 구분하고 표본 수·검증 한계를 생략하지 않는다.
- 새 결정 기록이 필요해지면 `docs/decision-log/`를 만들고 `PROJECT_GUIDE.md`에는 요약과 링크만 반영한다.
- 프로토타입·설문·분석은 `PROJECT_GUIDE.md`의 현재 범위와 다음 단계를 확인한 뒤 진행한다.
- 이 프로젝트는 별도의 `Worklog.md`를 두지 않는다. 진행 중인 작업 추적(문제·종료조건·결론)은 워크스페이스 루트의 `_meta/01_Worklog.md`에 남기고, 확정된 사실만 위 규칙대로 `PROJECT_GUIDE.md`·`docs/decision-log/`에 반영한다.
- **`_ai원본_백업/`은 에이전트가 참고하지 않는다.** 2026-08-22 이전 AI가 작성한 해석·결론의 원본 백업이며, 사용자가 실력 향상을 위해 `docs/`·`PROJECT_GUIDE.md`를 직접 다시 쓰기로 한 뒤 남겨둔 것이다. 사용자가 명시적으로 열람을 요청하지 않는 한 이 폴더를 읽거나, "직접 작성" 빈 칸을 채우는 데 이 폴더의 문장을 참고하지 않는다.

## "직접 작성" 빈 칸을 채울 때 (2026-08-22 추가)

`docs/`·`PROJECT_GUIDE.md`의 일부 절은 사용자가 실력 향상을 위해 "직접 작성"이라는 빈 칸으로 남겨뒀다(어느 절인지는 각 파일 안에 표시돼 있음). 이 빈 칸을 채우는 걸 도울 때는 아래 방식을 따른다 — 에이전트 종류(Claude Code, Codex 등)와 무관하게 동일하게 적용한다.

1. **판단을 대신 내려주지 않는다.** 빈 칸에 들어갈 결론·해석은 사용자 머리에서 나와야 한다. 표를 보고 에이전트가 스스로 해석해서 채우면 원래 목적(실력 향상)이 사라진다.
2. **근거가 되는 사실(표·스크린샷·수치)을 먼저 채팅에 직접 보여준다.** "위 표를 보라"처럼 파일을 참조만 하지 않는다 — 사용자가 그 순간 그 문서를 보고 있다고 가정하지 않는다.
3. **빠른 선택지 형태로 판단을 유도한다.** 자유 서술을 요구하기보다, 근거가 갈리는 지점에서 2개 내외의 실제 해석 후보(하나는 데이터가 뒷받침하는 것, 하나는 그럴듯하지만 반박되는 것)를 제시하고 고르게 한다. 사용자가 "모르겠다"고 하면 개념을 비유·예시로 더 풀어서 설명한 뒤 다시 고르게 한다 — 답을 대신 주지 않는다.
4. **사용자가 고른 뒤에만 파일에 반영한다.** 사용자의 표현을 최대한 살려서 옮겨 적는다.
5. **이미 배포되거나 실행 중인 결과물(예: `prototype/`의 배포된 Artifact, 참가자 테스트 기록, ThinkCode에서 별도 진행 중인 구현)에 영향을 주는 변경이면, 그 파급 범위를 먼저 설명하고 진행 여부를 확인받은 뒤에만 문서를 고친다.** 특히 이미 완료된 참가자 테스트 결과의 유효성에 영향을 주는 변경은 반드시 먼저 알린다.
6. 진행 상황(어느 파일의 어느 절까지 끝났는지)은 이 폴더의 `_meta/HANDOFF.md`에 남긴다 — 세션이 바뀌어도 이어갈 수 있도록.
