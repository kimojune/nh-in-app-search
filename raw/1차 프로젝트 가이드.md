# 01. 1차 프로젝트

<aside>

5일 동안 직무별 주제 하나를 골라, **포트폴리오에 넣고 면접에서 설명할 수 있는 수준**의 결과물을 만듭니다. 화면·기능 나열이 아니라 **문제 정의 → 제작 → 수치로 증명 → 설명**까지 하나의 이야기로 만드는 것이 목표입니다.

</aside>

## 프로젝트 제작 원칙

1. **실제에 준하는 데이터·상황으로 검증** (예시 한두 건이 아니라 여러 건과 까다로운 경우)
2. **수치 지표 하나 이상으로 개선 증명** (직군별 지표는 각 프로젝트에 명시)
3. **안정성** (이상 입력·실패·안전 문제를 방어하고 작동을 보임)
4. **재현성** (다시 돌려도 결과가 일정)
5. **설계 문서 + 회고** (왜 그렇게 설계했고, 무엇을 맞바꿨고, 한계는 무엇인가)

> 5일 범위 팁: 완제품이 아니라 **핵심 한 줄기를 깊게 + 실제 데이터 검증 + 지표 하나 + 문서**

## **일정 진행 흐름**


| **일차** | **초점**   | **주요 활동**                              |
| ------ | -------- | -------------------------------------- |
| 1일차    | 문제 · 데이터 | 문제와 사용자 정의, 실제 데이터·점검용 자료 확보, 성공 지표 설정 |
| 2일차    | 핵심 제작    | 핵심 기능/화면/문서 첫 버전, 실제 데이터로 첫 실행         |
| 3일차    | 안정성      | 이상 입력·실패·편향·민감정보 방어, 확인 관문 추가          |
| 4일차    | 평가       | 지표 측정, 개선 전후 비교, 실패 원인 분석              |
| 5일차    | 문서 · 발표  | 문서와 데모 정리, 설계 판단과 한계 발표                |


## **평가 기준 (포트폴리오 기준)**


| **항목**   | **확인 내용**             | **배점** |
| -------- | --------------------- | ------ |
| 문제 정의    | 실제 문제와 사용자를 명확히 정의했는가 | 15     |
| 동작 · 완성도 | 실제 데이터/상황에서 제대로 돌아가는가 | 20     |
| 성능 지표    | 직군에 맞는 수치로 효과를 증명했는가  | 20     |
| 안정성      | 실패·안전 문제를 방어했는가       | 15     |
| 재현성      | 반복해도 결과가 일정한가         | 15     |
| 문서 · 회고  | 설계 판단과 한계를 설명했는가      | 15     |


## **PO · 기획 (택1)**

- **채용에서 보는 것**: 문제 정의·우선순위, 데이터 기반 의사결정, 사용자 이해, 요구사항·스펙, 이해관계자 커뮤니케이션, 실행력.

### **트랙 A. 0에서 1 기능 기획 + 검증**

- 문제 정의 · 사용자 조사 → 기획서(PRD) → 성공 지표 구조 → 프로토타입(ThinkCode) → 사용성 테스트 또는 실험 설계.
- 난도 핵심: 지표로 성공을 정의하고, 소규모 검증으로 근거 확보.
- 산출물: 기획서 + 지표 구조 + 프로토타입 + 검증 결과.

### **트랙 B. 데이터 기반 개선**

- 공개 데이터나 피드백에서 문제 발견 → 개선 가설 → 지표 → 실험 설계 → 결과 해석과 다음 액션.
- 난도 핵심: 가설과 지표와 실험을 논리적으로 잇고, 숫자로 말하기.
- 산출물: 문제 진단 + 실험 설계서 + 분석 리포트.

> 상위로 보이려면: 맞바꾼 것과 우선순위의 근거, 이해관계자를 설득하는 논리를 문서에 담기.

<aside>  

💡

ThinkCode 내에서 아래 총 2가지 사항 제출이 필요합니다.

</aside>

1. **동작하는 결과물**: 링크 또는 실행 가능한 형태로 제출
2. **발표 자료(설명 문서)**: 문제 정의 · 구조 · 설계 판단과 맞바꾼 것 · 사용법
  1. **평가 리포트**: 지표 · 개선 전후 · 실패 원인 분석
  2. **회고**: 한계와 다음 단계
